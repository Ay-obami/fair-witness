# Final audit scope and trust limits

Reviewed source at `35f03e7`, with a bounded agent-only sponsorship accounting change. This is a source/test review, not an independent formal audit or a live attestation of deployed state.

| Boundary | Source behavior and review evidence | Limit |
| --- | --- | --- |
| Policy transitions | Owner-only mode change increments policy epoch; hash includes chain, treasury, policy and mode. Old proposals fail after a pause/resume. Universal policy values are constructor-set. Treasury tests cover mode invalidation, pause and irreversible closure. | Owner can register/revoke agents, transfer ownership and exit production funds. A registered agent can consume the attempt cap. |
| Evidence identity/replay | Verifier binds receipt index to Merkle path, source chain, observer and pool. Confirmation must be newer and within the immutable block gap; its age is checked against latest attested height. Proposal, nonce and execution-key maps prevent their respective replays. | Freshness is relative to latest attested height, not wall-clock age; stalled attestations require operational monitoring. Source observation may be older than the confirmation by the allowed gap. Execution keys include strategy/action, so evidence may support different strategies or different treasuries within their independent caps. |
| Venue, tokens and allowances | Immutable WCTC/STABLE/adapter route; adapter verifies router/factory/pool/fee tuple and token decimals, exact input consumption and actual output matching the router report. Exact approvals are cleared after success; failed external execution rolls back approval and movements. | Depends on token/router/pool and native verifier behavior. Nonstandard or mutable dependencies require separate review. |
| Slippage and caps | Universal slippage ceiling, strategy direction/value checks, nonzero minimum output, execution/attempt epoch caps, and daily risk usage. Failed swaps roll back execution/evidence/risk state while retaining the failed attempt and consumed proposal/nonce. | Value caps depend on attested price and destination oracle assumptions. Risk daily usage charges the permitted ceiling rather than actual smaller trade value, conservatively reducing availability. This is no profitability guarantee. |
| Recovery and isolation | Production owner exit sends pair tokens only to owner; closure pauses permanently. Demo withdrawals are blocked and closure recycles to reserve. Each treasury owns its registration, counters and journal; chain/treasury hashing prevents cross-tenant proposal identity reuse. | Shared agent/sponsor service availability and shared credentials remain operational risks. Public Supabase mappings are untrusted convenience data; dashboard factory/owner validation is authoritative. |
| Release alignment | CI rebuilds creation code and compares hash/size to lifecycle manifest, regenerates agent/frontend ABIs and checks release references. No Solidity change in this patch. | These checks compare committed local artifacts. They do not establish today's deployed runtime, RPC availability, reserves, roles or current automation state. No network write is authorized by this review. |
| Sponsorship | Fresh wallet signature remains required. Durable locked principal reservation is written before send, retained on ambiguity/failure, and shared across restarts. Regression tests exercise restart, cooldown/day rollover, independent instances, corruption, lock, identity and clock rollback; HTTP test exercises signed requests and mocked ambiguous broadcast. | Requires persistent local storage and one sender per sponsor wallet. A stale lock fails closed and needs reconciliation; `/health` may still report process health while that lock blocks top-ups. Principal budget excludes fees. Anyone can create wallet identities and exhaust the bounded demo budget; operator deletion/rollback of ledger and independent spending are outside protection. |

Existing contract tests cover stale proof boundaries, forged receipt indices, policy/replay rejection, oversized actions, wrong venue/slippage, failed swap rollback, fixed routes, lifecycle recovery and independent factories. Regression scenarios are documented in [the adversarial test matrix](ADVERSARIAL_TEST_MATRIX.md); live public testnet state was not refreshed or changed.
